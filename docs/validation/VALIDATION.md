# TrustedRisk validation report

This file aggregates the validation evidence for TrustedRisk's clinical
decision-support tools. It covers three layers of validation:

1. **Calibration validation** -- does the readmission risk model produce
   reliable probabilities on out-of-distribution data?
2. **Subgroup fairness** -- does the model perform equitably across
   demographic groups?
3. **Tool regression** -- do the rule-based tools produce stable outputs
   over time?

## 1 Calibration on external cohorts

The calibrated readmission-risk model (`lace-plus-bayesian-v1`,
`spec_002`, 5-bin Beta-Binomial) was originally fit on a Synthea synthetic
cohort (n=7780) with mean LACE ~7. We validate it on **two** external
cohorts:

1. **MIMIC-IV demo 2.2** -- real ICU/ED encounters, n=275 admissions
   from 100 patients (open access, PhysioNet). LACE features extracted by
   `scripts/mimic_iv_to_lace.py` (LOS from admit/disch timestamps;
   acuity from `admission_type` ∈ {URGENT, EMERGENCY, ...}; Charlson
   proxy from distinct ICD-10 chapter prefixes; ED visits from prior
   urgent/emergency admissions in the 180 days before; 30-day readmit
   from any subsequent admission within 30 days of discharge).

2. **Synthetic cross-shifted cohort** -- n=500, generated by
   `scripts/external_validation.py --synthetic` to stress-test the model
   on a deliberately harder distribution (mean LACE ~9, outcome rate ~46%
   with race + insurance effects).

### Synthetic cross-shifted cohort

This cohort is the stress-test counterpart, deliberately harder.

### Cohort

- **Source**: synthetic cross-shifted cohort (n=500), generated by
  `scripts/external_validation.py --synthetic`
- **Distribution shift vs training**:
  - Mean LACE bumped from ~7 to ~9 (3rd-tier acuity bias)
  - Outcome rate amplified from ~11% to ~46% (urban safety-net hospital
    proxy)
  - Demographic mix: 40% white / 30% Black / 18% Hispanic / 7% Asian / 5%
    unknown; 50% Medicare / 25% Medicaid / 20% private / 5% uninsured
- **Outcome generation**: logistic on LACE features with small additional
  effects for race=Black (+0.30 logit) and insurance=medicaid/uninsured
  (+0.20 logit), to test the fairness audit's ability to surface drift

The synthetic cohort is a stand-in; replacing it with the MIMIC-IV demo
or any local cohort CSV is a one-line swap (`--input cohort.csv`).

### Overall calibration metrics

| Metric          | Value     | Reading |
|-----------------|----------:|---------|
| N               | 500       | |
| Brier score     | **0.300** | Worse than ideal (~0.10 for a well-calibrated model on similar prevalence). Reflects the deliberate distribution shift. |
| ECE (10 bins)   | **0.252** | Large miscalibration: the model UNDER-predicts on this cohort. |
| MCE (10 bins)   | **0.353** | Maximum calibration error in any bin |
| AUROC           | **0.650** | Moderate discrimination -- better than the 0.59 reported on training, suggesting the LACE features generalise even when calibration drifts |
| Mean predicted  | 0.20      | |
| Observed rate   | 0.46      | |
| Calibration gap | **-0.25** | Systematic UNDER-prediction by 25 percentage points |

**Interpretation**: the LACE features still discriminate (AUROC 0.65),
but the absolute probabilities are far too low for this cohort. This is
exactly the scenario the runtime is designed to handle: the **abstain
trigger** (`confidence_interval_too_wide` when `probability_ci_width
> 0.30`) AND the **fairness audit** (`max_relative_drift > 0.20`) both
fire. The user-facing recommendation is downgraded or held.

## 2 Subgroup fairness analysis

`scripts/external_validation.py` computes Brier + AUROC + calibration gap
for each demographic subgroup with bootstrap 95% CIs (n=500 bootstraps).
Full numbers in `docs/validation/calibration_metrics.csv`.

### By race (n=500)

| Race      |   N | AUROC (95% CI)         | Calibration gap | Brier |
|-----------|----:|------------------------|----------------:|------:|
| White     | 199 | 0.604 (0.512–0.670)    | -0.271          | 0.316 |
| Black     | 152 | 0.695 (0.634–0.801)    | -0.271          | 0.301 |
| Hispanic  |  86 | 0.539 (0.492–0.717)    | -0.227          | 0.291 |
| Asian     |  39 | 0.652 (0.472–0.823)    | -0.208          | 0.272 |
| Unknown   |  24 | 0.562 (0.317–0.858)    | -0.141          | 0.237 |

**Reading**: the calibration gap is consistent (-0.20 to -0.27) across
race groups -- the model's under-prediction is NOT race-specific in this
cohort. AUROC varies more (0.54 Hispanic vs 0.70 Black), but small-N
subgroups have wide CIs.

### By insurance (n=500)

| Insurance | N   | AUROC (95% CI) | Calibration gap |
|-----------|----:|---------------:|----------------:|

**Reading**: uninsured has the largest calibration gap (-0.285) consistent

## 3 Golden-case regression suite

`tests/golden/cases/*.json` -- **36 hand-authored** golden cases across
**~18 distinct tools** that assert subset-match on key output fields.
The suite catches:

- threshold drift (e.g. someone changes the C-SSRS imminent threshold
  without updating the test)
- schema additions that accidentally rename existing fields
- coefficient drift after a coefficients.json refresh

| Domain                  | Cases | Tools covered |
|-------------------------|------:|---------------|
| Stroke severity         |     3 | compute_stroke_severity |
| HEART score             |     3 | compute_heart_score |
| Preeclampsia (ACOG 2020)|     4 | compute_preeclampsia_assessment |
| Trauma + MTP            |     4 | compute_trauma_severity_score, compute_massive_transfusion_protocol |
| DKA + AKI + Dialysis    |     5 | compute_dka_severity, compute_aki_kdigo_stage, compute_dialysis_initiation_decision |
| Imaging + contrast      |     6 | compute_imaging_appropriateness, compute_contrast_safety_check |
| Mental health + Pediatric |   6 | compute_suicide_risk_assessment, compute_psychiatric_admission_decision, compute_pediatric_early_warning, compute_weight_based_dosing |
| Falls + delirium + NEWS2 |    5 | compute_falls_risk_morse, compute_delirium_screening_cam, compute_clinical_deterioration_score |

Each case has the form:

```json
{
  "name": "human-readable case label",
  "input": { /* tool kwargs */ },
  "expected_subset": { /* fields whose values must match */ }
}
```

The runner is `tests/golden/test_golden_cases.py`. CI fails if any
golden case drifts.

## 6 Decision trail + audit log (AUDIT-1, AUDIT-2)

`src/a2a_agent/audit.py` provides:

- **HIPAA-style structured audit log** at `data/audit.jsonl` (JSONL,
  append-only). Every tool call is logged with `request_id`,
  `tenant_id`, `tool`, `input_hash` (SHA-256 of redacted input),
  `output_hash`, `bundle_used`, `abstain_triggered`, `agreement`. PHI
  fields (name, MRN, DOB, address, phone, email) are stripped before
  hashing -- the audit retains forensic value without leaking patient
  data.
- **Reproducibility archive** at `data/reproducibility_archive.sqlite3`
  (per-decision snapshot of redacted inputs + outputs + coefficients
  version + tool versions + env snapshot).
- **`check_reproducibility(request_id, replay_fn)`** replays an archived
  decision and verifies byte-identical output via SHA-256 comparison.

Playground endpoints:

- `GET /api/audit/log?limit=N&request_id=...&tenant_id=...&abstain_only=true`
- `GET /api/audit/archived-decisions?limit=N`
- `GET /api/audit/reproducibility/{request_id}` -- pre-flight check
  (compares archived vs current coefficients version)

## 7 Synthetic cohort regression (DATA-1, DATA-2)

`scripts/generate_synthetic_cohorts.py` (seed 4242) generates **600
synthetic patient cases** across 12 bundle cohorts (50 per cohort)
covering 12 different tools. Each case has a realistic input
distribution (e.g. PEWS cohort biased toward sepsis-like infants;
HEART cohort split between low / moderate / high risk).

`tests/golden/test_bundle_cohorts.py` parametrizes over all 600 cases
and asserts schema validity + no crashes. Runs in ~1 second.

```bash
.venv/Scripts/python.exe scripts/generate_synthetic_cohorts.py
.venv/Scripts/python.exe -m pytest tests/golden/test_bundle_cohorts.py
```

## 8 How to re-run

### Calibration validation

```bash
PYTHONPATH=src TRUSTEDRISK_COEFFICIENTS_PATH=data/coefficients.json \
    .venv/Scripts/python.exe scripts/external_validation.py --synthetic
```

To validate against a real cohort, prepare a CSV with columns
`patient_id, age, race, insurance, lace_los, lace_acuity, lace_charlson,
lace_ed_visits_6mo, outcome_30d_readmit` and run:

```bash
PYTHONPATH=src TRUSTEDRISK_COEFFICIENTS_PATH=data/coefficients.json \
    .venv/Scripts/python.exe scripts/external_validation.py \
    --input path/to/cohort.csv
```

### Golden-case regression

```bash
PYTHONPATH=src TRUSTEDRISK_COEFFICIENTS_PATH=data/coefficients.json \
    .venv/Scripts/python.exe -m pytest tests/golden/ -v
```

### Adding new golden cases

Drop a new `*.json` file in `tests/golden/cases/`. The runner picks it up
automatically. Format example: `tests/golden/cases/heart_score.json`.

## 5 Known limitations

- **Synthetic external cohort**: the validation set is a synthetic
  cross-shifted distribution. It demonstrates the validation pipeline
  but does not replace evaluation on a real EHR cohort. Re-run with
  `--input` once a cohort is available.
- **Bootstrap CIs assume independent samples**. For longitudinal data
  with multiple encounters per patient, cluster-bootstrap is preferable.
- **Golden cases cover ~18 of the 58 tools** (the most clinically critical).
  The remaining tools (terminology crosswalks, external-knowledge retrieval,
  chart-intelligence, patient-facing rendering) are validated via the 181
  functional tests in `tests/functional/` instead.
  Tools whose output is dominated by complex composition (ground_claim
  with FAISS, decision_utility with Monte Carlo) are validated via unit
  tests with monkeypatched inputs rather than golden subset-match -- see
  `tests/unit/`.
- **No prospective validation**. All metrics are retrospective on
  historical or synthetic data.
